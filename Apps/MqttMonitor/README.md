# MQTT 实时数据监视平台

自带 MQTT Broker 的实时监视平台 —— 设备把 MQTT 地址指过来就能被监视，不用另外部署 EMQX / mosquitto。

- **自带 Broker**：平台自己就是一个 MQTT 服务端（默认监听 `1883`），带设备台账、可选账号鉴权、可踢客户端
- **也能当客户端**：随时切换到连接外部 broker（EMQX / mosquitto / 阿里云 IoT / 自家网关都行）
- **实时看板**：数值卡片 + 实时曲线（**带 X / Y 坐标刻度，X 轴时间范围可设**），带上下限告警（超限变红、接近限值变橙）
- **消息流水**：全量报文滚动、按主题过滤、暂停、导出 CSV
- **零前端依赖**：原生 WebSocket + Canvas，不依赖任何 CDN，断网也能跑

---

## 一、快速开始

双击 **`启动平台.bat`**（首次会自动装依赖），然后浏览器会打开 `http://127.0.0.1:8090`。

首次运行时平台会自动：启动内置 Broker（1883）→ 打开数据模拟器 → 平台自己接上去。
所以打开就能看到数据在跳，用于先熟悉界面。

> 接真实设备时，把模拟器关掉即可（左侧「内置 Broker」面板里的「数据模拟器」开关）。

命令行方式：

```bash
node server.js                 # 默认 Web 端口 8090，Broker 端口 1883
node server.js --port 9000     # 改 Web 端口
node server.js --broker-port 1884
node server.js --no-broker     # 不启动内置 Broker，只作客户端连外部 broker
node server.js --no-sim        # 内置 Broker 不开数据模拟器
node server.js --no-open       # 不自动打开浏览器
```

## 二、两种接入方式

### 方式 A：设备直连平台（用内置 Broker）

1. 启动平台，左侧「内置 Broker」面板确认状态是 `运行中 :1883`
2. 面板里会列出接入地址，例如 `tcp://192.168.7.103:1883`
3. 把设备的 MQTT 配置改成这个地址（ClientId 随便起，唯一即可）
4. 设备一发包，左侧「实时主题」就会出现新主题，点 `+` 上板；开着「自动上板」则自动完成

设备侧配置参考（任意 MQTT 库都一样）：

| 参数 | 值 |
|---|---|
| Broker / Host | 平台所在电脑的局域网 IP |
| Port | 1883（或你在面板里改的端口） |
| ClientId | 设备唯一标识，如 `kiln-01` |
| 用户名/密码 | 留空（默认允许匿名）；面板里设了账号才需要填 |
| 建议上报主题 | `厂区/设备名/测点`，例如 `plant/line1/temp` |

QoS 平台统一按 0 处理（周期上报场景够用，界面不再暴露这个选项）。

### 方式 B：设备连别的 broker，平台去看

左侧「连接设置」里填外部 broker 的地址/端口/账号，订阅主题填 `#`（或 `plant/#` 只订阅部分），点「连接」。

> 注意：这种方式下平台是"订阅方"，设备仍然连原来的 broker，平台不会替设备转发。

## 三、界面说明

**顶栏**：连接状态、消息速率、累计条数、主题数、在线时长；右侧两个下拉 —— **X 轴时间范围**（看板全局默认）、每行列数；再往右是暂停刷新 / 清空 / 连接断开。

**左侧栏**（默认只展开「实时主题」，其余点标题即可展开）

| 面板 | 作用 |
|---|---|
| 实时主题 | 收到过数据的主题清单，点 `+` 加到看板；底部三个开关：自动上板 / 示例看板 / 清空 |
| 内置 Broker | 启停自带的 broker、看设备台账、断开指定设备、开关数据模拟器 |
| 历史数据 | 已落盘多少条 / 占用多少 / 最早一条是什么时候；改保留天数、导出 CSV、清空历史 |
| 连接设置 | 平台作为客户端去连其它 broker 时填这里；下半部分是订阅管理（支持 `+` `#` 通配符，点 × 取消） |
| 下发测试 | 往任意主题发一条消息，用于测设备接收 |

> 没连上 broker 时，「连接设置」会自动展开，省得找不到。消息流水默认折叠在底部，点标题栏展开。

**看板卡片**

- 单击卡片 → 放大/还原（看大图曲线）
- 单击卡片右上角 ⚙ → 设置：显示名称、单位、**展示曲线（勾选字段）**、**X 轴时间范围**、上下限、点数上限
- 告警规则：超过上限/低于下限 → 红；进入限值内侧 10% 区间 → 橙；**超时无数据 → 状态标签变「无数据 X 分」**（下节详述）
- 卡片配置会存在 `config.json`，重启后自动恢复
- 提示：底部的「自动上板」勾着时，**新主题会自动加卡并一起存进 `config.json`**（所以浏览一遍就会多出一堆卡）。不想要的卡：单击卡片 ⚙ → 左下角「删除此卡片」

**载荷解析 —— 按数据类型自动出曲线**

不用说字段名，平台自己看报文长什么样：

| 收到的报文 | 卡片显示 | 曲线 |
| --- | --- | --- |
| 纯数字 `62.4` | `62.4`（保留设备上报的小数位） | 1 条 |
| JSON `{"temp":62.4,"pressure":0.83,"run":true}` | 主字段的数值 | **每个数值字段各 1 条线**（最多 6 条，超出显示 `+N`）；布尔字段当开关量，画成 0/1 台阶线 |
| JSON 里数值是**字符串** `{"value":"0"}` | `0` | 1 条。PLC / 网关 / OPC 转发常把数值发成 `"0"`、`"62.40"`，这种也认（显示保留设备原文，`"62.40"` 不会被规整成 `62.4`） |
| JSON 里数值**带单位** `{"temp":"62.4℃","p":"1.5 MPa"}` | `62.4℃` | 各 1 条。单位走白名单（℃ °C % mm cm km m MPa kPa Pa bar kg g t rpm r/min m³/h L/min Hz kHz kW W V mV A mA ms min s h），所以 `"3号工位"` 这类描述不会被误当成数字 3 |
| JSON `{"code":"W100","text":"1号线炉温高"}` | 原文 | 不画（没有可绘制的数值） |
| 其它文本 | 原文 | 不画 |

时间戳字段（`"ts":"2026-09-24T14:02:41+08:00"`）、型号名（`"dataType":"Int16"`）不会被误判成数字，放心把整条报文直接发过来。

- 多字段卡片会在数值下方显示**图例**（色点 + 字段名 + 当前值），一眼看得出哪条线是哪一路
- 每条曲线**各自归一化** Y 轴：`62.4` 的温度和 `0.83` 的压力画在一张卡上时，两条都能看出趋势，不会有一条被压成平线

**曲线上的 X / Y 坐标值**

每条曲线上都带坐标刻度，不用再靠猜：

| 位置 | 内容 | 说明 |
|---|---|---|
| 绘图区左缘 | **Y 轴数值**，水平网格线 | 刻度值自动取整成 `1 / 2 / 5 × 10ⁿ` 的"好看"步长，不会出现 `3.333` 这种刻度 |
| 绘图区底部 | **X 轴时间**（多个） | 按可用宽度**能标几个标几个**，首尾一定贴住绘图区两端，中间按数据点的真实位置居中 |
| 鼠标悬停处 | **该点的 X（时间）+ 每条曲线的 Y（值）** | 竖向虚线 + 高亮点 + 悬浮提示框，见下一节 |
| 多曲线卡片 | Y 刻度用**主曲线的颜色** | 刻度属于哪条线一目了然 |

几个细节：

- X 轴时间**按跨度自动选格式**：跨度大于 1 分钟只标到 `HH:MM`（`12:38`），跨度小于 1 分钟才带秒（`12:38:49`）——窗口里 40 分钟的曲线标到秒纯属占地方
- 大数值自动缩写：`12500` → `12.5k`、`1000000` → `1.0M`
- 曲线是**按索引等距**画的，所以 X 轴只标真实存在的时间，不编造等分刻度
- 多曲线卡片 Y 轴**只能有一个量程**（各条线各自归一化、量程本就不同），所以取主曲线的刻度并标明归属
- 刻度条数**按绘图区高度自适应**：小卡片（44px 高）给 2~3 档；**单击放大后有 5~8 档**，量程一眼到位。刻度会先按 `niceTicks` 取"好看"步长，再按能排下的条数**等距**抽稀（抽稀只跳整倍数，保证剩下的仍然等距 —— 刻度不等距比刻度少更糟，读数会按错误的步长去估）
- X 轴标签是**量出来的**：先实测一条时间文字有多宽，再看绘图区宽度能放下几个（最多 3 个 / 放大后 5 个），所以窄卡片不会挤成一团、宽卡片也不会中间空一大段

**鼠标悬停读任意一点的值**

在曲线上滑动鼠标，竖线会**吸附到最近的那个真实数据点**（不是插值出来的位置），提示框给出这一点的 X 与 Y：

- **X = 时间**：`14:32:05`（跨天会带上日期 `09-30 14:32:05`）
- **Y = 值**：只显示该曲线**真实采样**到的那一个值，不做平均、不做插值 —— 看到 `680` 就是设备当时报的 `680`
- **多曲线按时刻对齐**：竖线只有一根。几条曲线各自算"离鼠标最近的点"会各指一个时间，读数看起来就自相矛盾了；这里是先定基准曲线（点数最多、覆盖时段最完整的那条）的那一列，其余曲线按**时间戳**取同一时刻的点
- **单曲线**额外画一条横向虚线指向左侧 Y 刻度，方便对着刻度读数；多曲线不画横线（各自量程不同，一条横线会指向错误的刻度）
- 悬停只重画**独立的覆盖层**（十字线 + 高亮点），不动主曲线的画布 —— 移动鼠标是跟手的，数据在实时更新时十字线也跟着新点位走
- 提示框挂在 `<body>` 上（`position: fixed`）：卡片是 `overflow: hidden` 且 `:hover` 时带 `transform`，放在卡片里会被裁掉
- 滑出绘图区、鼠标离开画布、看板滚动，都会把十字线收掉（提示框是 fixed，不跟着滚会停在原地指错点）

**X 轴时间范围可设置**

只想看最近一段，不想被几小时前的数据挤扁：

| 在哪设 | 作用 |
|---|---|
| **顶栏「X 轴」下拉** | 全局默认，一改全变。可选 全部 / 1 / 5 / 15 / 30 分钟 / 1 / 4 / 24 小时 / 3 天 / 7 天 |
| **卡片 ⚙ → X 轴时间范围** | 单张卡片覆盖全局；选「跟随顶栏全局设置」就回到跟随 |

两个层级叠加的规则：**卡片自己设过就用卡片的（包括显式选「全部」），没设过才跟随顶栏**。改全局时，已经单卡设过的卡片不会被带着走，提示里会告诉你有几张没受影响。

**「显示多久」和「画多少个点」是两回事**——这是最容易被搞混、也最容易误以为"数据丢了"的地方：

| 旋钮 | 管什么 | 默认 |
|---|---|---|
| **X 轴时间范围** | 显示**多久**（时间跨度） | 全部（保留期内） |
| **卡片 ⚙ → 点数上限** | 最多画**多少个点**（分辨率安全阀） | 留空 = 不限 |

- 选了「最近 1 小时」，平台会**从落盘库里把那一小时的数据捞回来**画满——不是只画内存缓冲里那几十个点。数据跨度由窗口决定，不由点数决定。
- 「点数上限」只在设备上报很快时兜底。超上限时是**均匀抽稀**（整段窗口还在，只是点稀了），**不是把前面的数据丢掉**。
- 卡片右下角会写明这次的实际情况，例如 `1320/5001 点（抽稀） · 10.0 小时 · 库内 30000 条`——一眼看出"画了多少点、铺开了多久、库里还有多少"。
- 「全部」= 保留期内库里的全部数据（超过 5000 个点时在服务端均匀抽样，首尾必留）。

两个容易踩的点：

- **窗口锚在「该卡片最新一条数据的时间」，不是电脑当前时间。** 设备停发、或刚刷新页面从库里回填历史时，如果锚 `Date.now()`，窗口会一直往前滑、把所有数据甩出去，曲线整屏变空 —— 看着像数据丢了。现在卡片脚部的最后时间仍然是真实时间，配合灰显「无数据」就能判断设备是否掉线。
- **窗口比库里的数据还长时，界面会说实话。** 例如库里只有 10 小时数据、你选了「最近 7 天」，曲线还是 10 小时，并提示「库里也只有这么多数据」——不会假装显示满，也不会把曲线清空。

**超时无数据提示**

设备不发了，看板必须一眼能看出来 —— 分三级：

| 位置 | 表现 |
| --- | --- |
| 卡片状态标签 | **单主题卡**：`无数据 3 分`；**分组卡整组静默**：`无数据 3/3`；**分组卡只挂掉几个点位**：`无数据 1/3`（红字，这种最隐蔽） |
| 卡片整体 | 整卡没数据时左边条转灰、底色压暗一档、大字转灰（**只对"整卡真没数据"生效**——部分掉线时卡片本身还活着，把大字一起转灰会让人以为整张卡都死了） |
| 顶栏 | 一行汇总，如 `⚠ 2 张卡片无数据 · 1 张卡有 3 个点位掉线`。**点一下跳到第一张出问题的卡片**并闪一下，悬停有明细。没问题时整条隐藏 |
| 消息提示 | 掉线、恢复各弹一次提示（**边沿触发，不常驻刷屏**；页面刚打开时若本来就有一堆卡掉着，只记基线不弹） |

分组卡有个**卡片级判定看不见的盲点**：`isStale()` 看的是"卡片上最新的一条数据"，所以 `plc/A`、`plc/B`、`plc/C` 里只挂掉 `A` 时，整张卡照样显示「正常」，`A` 那个点位会拿一条 10 分钟前的旧值一直摆着，看着像还活着。现在补了**逐成员判定**：每个主题自己记上报间隔（`gaps`），用**它自己的节拍**算阈值（各点位节拍可能差很远，拿卡片级的节拍去判会把慢的那个一直误报成掉线），停发了就把它的图例行撤成「—」并标橙，同时参与上面那三级提示。

掉线点位的曲线也不许当"当前值"：分组卡没勾选时主曲线兜底取 `series[0]`，往往正是第一个上报的点位 —— 它掉线后大字会把旧值一直摆着。现在大字和 Y 轴刻度都会改挑一条还在发的；全掉线了才老实显示「—」。

**"估不出节拍"不等于"掉线"** —— 这条是拿线上实测换来的：

> 阈值来自**实测节拍**（最近 12 个间隔的中位数 ×3）。页面刚打开、历史还没回填完的那几十秒里，卡片手上只有一两条报文、**一个间隔都估不出来**。旧实现这时退回 15 秒兜底去判，于是现场 60 秒节拍的设备每次上报后 15 秒就变「无数据」—— 实测 8 张卡里有 4 张在闪、顶栏还跟着报「2 张卡片无数据」，全是误报。
>
> 现在**判不了就返回 null，调用方跟着不判**；15 秒只在下限的意义上使用 —— 即*估出来的*节拍 ×3 不足 15 秒时才抬到 15 秒。代价是"只报过一次就再没消息"的点位不会被标出来（卡片仍会显示它的最后值与时间戳），换掉一整类误报，划算。

**选定消息字段展示曲线**

在一个 JSON 报文里挑哪几路来画，不用记字段名：

1. 单击卡片 ⚙ → 「展示曲线」区会**列出这条主题报文里所有可画的字段**（色点 + 字段名 + 当前值，开关量额外标注）
2. 勾上要看的字段（最多 8 个）→ 保存。卡片下方提示会从「当前自动：全部都画」变成「已选 2 / 8 个字段」
3. 一个都不勾 = 自动模式（所有数值字段都画）；点「全部取消」可一键回到自动
4. 报文里暂时没出现过的字段（比如嵌套较深、或还没上报过），填在「额外字段路径」里，多层用 `data.temp`，逗号分隔多个
5. 列表里没有你要的字段？提示行会说明还剩几个**文本字段**（如 `description`、`dataType`）——文本画不了曲线，只能画数值

勾选后卡片大字与告警判定取**第一个勾上的字段**。字段列表来自该主题最近一条报文，所以先让设备发一条再看设置最准。

**同一台设备一张卡（按主题前缀分组）**

现场常是这样：**同一台 PLC 的点位发在不同的主题上** —— `plc/DB1.DBW290` 是电池电量、`plc/DB1.DBW292` 是电池电流。默认一卡一主题，于是同一台设备的电量电流被拆成两张卡，时间轴还对不齐，看趋势得来回瞄。

分组卡片把「主题前缀」当成一台设备。两种用法：

**① 自动（默认开，不用管）**——侧栏「实时主题」面板底部有 **「同前缀自动合并」**：

- 同一个前缀下的主题**自动进一张卡**，每个主题一条曲线。`plc/DB1.DBW290` 先上报、`plc/DB1.DBW292` 后上报，最后看板上只有一张「plc」
- **已经各占一张卡的老看板也会在下次刷新时并起来**（卡片是收到报文才上板的，先来的那张当时并不知道后面还有兄弟主题）
- 再来同前缀的新主题，直接进这张卡，不会再冒一张新卡
- 关掉开关：不再自动合并，已经并好的卡保持原样（想拆开就在那张卡 ⚙ 里取消「按前缀分组」）
- 判断依据是**父路径**：`plc/DB1.DBW290` 的父路径是 `plc`；多层（`a/b/c`）归到 `a/b`；没有 `/` 的裸主题不参与合并（判断不出属于哪台设备）

**② 手动**——任意一张卡片 ⚙ → 勾上 **「按前缀分组：这个前缀下的所有主题放进同一张卡」**：

1. 主题填前缀：`plc` / `plc/` / `plc/*` / `plc/#` 都行，都会归一成 `plc`
2. 保存 → `plc/` 下的**每个主题各一条曲线**，全在一张卡上（最多 6 条，超了图例末尾老实写 `+N`）

配套的几个行为：

| 场景 | 表现 |
|---|---|
| 卡片副标题 | `plc/*　6 个点位`——一眼看出收了几个点位，还没数据时写「等待数据」；勾选模式下写成 `1/2 个点位`（画了 1 条 / 一共 2 个） |
| 侧栏 | 被分组卡收着的主题标紫点 + 紫色 ✓，提示「已在分组卡「plc/*」里 · **点一下把它从卡片上撤下来**」；**点 ✓ 就是"取消上板"**，撤下来的主题变空心紫点 + 虚线 `+`，再点 `+` 直接加回那张卡（不会另冒一张单主题卡） |
| 前缀边界 | **按 `/` 切**：`plc` 只收 `plc/…`，不会把 `plc2/…` 抢走；多层前缀（`a/b`）也支持，冲突时**最长前缀优先** |
| **只看其中几个主题** | ⚙ → 每个主题一个勾选框：**勾上 = 画它的曲线；不勾 = 仍然留在卡片上显示实时值，只是不画线**（图例里是空心灰点）。一个都不勾 = 自动（按顺序画前 6 条），点「全部取消」一键回到自动 |
| **某个主题不想要了** | ⚙ 里那一行右边的 ✕，或者侧栏点它的 ✓ —— 都是「取消上板」：值、曲线一起从卡片上撤掉，之后它再上报也不会自己爬回卡片。反悔：⚙ 底部「已从卡片删除（N）」点「恢复」，或侧栏点 `+` |
| 某个主题想画别的字段 | ⚙ 里**每个主题一行下拉**，选「这条曲线画该主题里的哪个 tag / 字段」，留「自动」就按"测点身份 → 整条数值 → 第一个数值字段"取 |
| 刷新页面 | 每个成员主题**分别**去落盘库回填历史（不是只补最新那个），列表和颜色顺序都稳定，勾选状态也一起恢复 |
| 取消分组 | 取消勾选、主题改成完整主题名 → 回到普通单主题卡，曲线立刻从库里重建 |

关于勾选的两个细节：

- **勾选也受「一张卡最多 6 条曲线」限制**：勾到第 7 个会被弹回去并提示，不会画出第 7 条糊成一团
- **没勾的主题照样占图例一行**（显示它的实时值），所以 `+N` 表示"连图例都排不下的点位"。想把某条曲线找回来，进 ⚙ 勾上、或点「全部取消」

几个刻意的设计：

- **自动上板不会替你"猜"分组** —— 它只按父路径归并**同一个前缀下**的主题（那是能确定的）；跨前缀的合并要你自己动手（把一张卡改成分组卡、填上公共前缀）。
- **成员清单取"见过的 + 内存里的 + 落盘库里查到的"三者并集**。刷新页面后内存里一条报文都没有，光靠"见过的"会漏掉整组。
- 分组卡和普通卡一样存进 `config.json`（多存 `group` / `picks` / `picked` / `removed` 四个字段），重启后自己恢复。
- **回填去重是"按主题"的**：主题被撤下再放回来时，它那条回填记录一起作废 —— 否则"卡片|窗口|起点"没变，回填会被当成重复请求跳过，放回来的主题就一直只有实时值、曲线空着。
- **纯靠回填补出来的曲线也要有"当前值"**：刚把某条曲线切到另一个字段时（现场设备 60~80 秒才发一条），曲线已经画上一串点，但 `num/text` 还是空 —— 大字和图例会挂着「—」，看着像没数据。所以合并历史时用最新那个点补成当前值，实时报文一到立刻覆盖。
- 合并**不丢已经画出来的数据**：并完会立刻按前缀去库里把每个主题的历史拉回来（库读接口前会先把攒批队列刷干净，所以刚收到的点也在）。
- 合并只动"父路径下有兄弟主题"的卡；你自己改过的卡片名字（如「1号炉」）会保留，只有还叫旧主题名的才跟着换成前缀。

**消息流水**：时间精确到毫秒、可按主题关键字过滤、可暂停滚动（数据仍在接收）、可导出 CSV（带 BOM，Excel 直接打开不乱码）。

### 前端自检（无头 Edge + CDP）

界面改动用肉眼看容易漏（尤其是 canvas 画出来的东西），下面几个脚本会真的开一个无头 Edge 去点、去量、去截图：

```bash
node tools/check-ids.js            # app.js 里取的 DOM id 和 index.html 是否对得上
node tools/verify-history-ui.js    # 「历史数据」面板：统计填充、按钮可点、保留天数真的写进配置（20 项）
node tools/verify-axis-ui.js       # 曲线坐标轴 + X 轴时间范围（97 项）
node tools/verify-chart-full.js    # 「曲线显示不全」：库里 30000 条 / 跨 10 小时，断言真的全画出来（65 项）
node tools/verify-items.js         # 一个主题多测点（按 tag/address 分组）+ 勾选画哪几条（44 项）
node tools/verify-hover.js         # 鼠标悬停读任意一点的 X/Y + 刻度密度（89 项）
node tools/verify-group.js         # 按主题前缀分组：一台设备一张卡 + 勾选画哪条 + 取消/加回上板 + 自动合并 + 超时无数据提示（156 项）
node tools/live-peek.js            # ★ 只读看**线上**看板现状（拦掉 /api/cards，不动现场配置）；PEEK_WAIT_MS=16000 复现"刚打开还没回填完"的时序
```

> 上面这些合计 **532 项断言**（再加 `check-ids.js` 的 88 个元素 id）。

`verify-axis-ui.js` 的看点：它**勾住 `CanvasRenderingContext2D.prototype.fillText`**，把"画了哪些文字、画在哪个坐标、什么对齐方式"全记下来再断言 —— 比去数 canvas 像素点可靠得多（曲线本身也是像素，会干扰判断）。同时把 `niceTicks` / `fmtAxisTime` / `windowLabel` 等纯函数从源码里抠出来做单元断言（`REPORT_JS` 这类模板字符串里的 `${}` 记得转义，否则会被 Node 抢先求值）。

X 轴范围那部分是这样验的：造**两张数据完全一样**的卡片（各 40 分钟、每分钟一点），一张跟随全局、一张单卡覆盖成「全部」，把全局改成 15 分钟后断言前者的 X 轴首标签正好是「最新点 − 15 分钟」、实际画出 16 个点，而后者仍是完整 40 分钟 —— 读的是产品自己挂在卡片上的 `card._chart`，不是探针另写一套窗口逻辑。

`verify-chart-full.js` 专门盯「曲线显示不全」这个坑：它直接往临时 SQLite 里写 **30000 条 / 跨 10 小时**的数据（不用经过 broker，几秒钟就造好），然后断言 —— 页面进内存的不是 120 个点而是 5000+、X 轴第一个刻度正好是库里最早那条数据的时间、把「点数上限」设成 50 之后**点数变少但铺开的时间跨度不变**（证明确实是抽稀不是截断）、窗口设成 7 天时界面说实话而不是假装画满。它还顺手验了服务端 `sample=1` 的均匀抽样（对照 `sample=0` 只给最新一段，跨度 0.17 小时 vs 10 小时）。

它最后两个阶段专治"看起来像显示问题、其实是时序问题"：

* **阶段 G —— 刷新页面时"实时点先到"的顺序陷阱。** 页面一打开 WebSocket 就连上了，服务端会**回放最近一条报文**；紧接着历史回填才把更早的数据灌进来。如果历史是 `append` 进去的，`ts` 就变成 `[最新, 更早, 更早…]` —— 窗口裁剪游标失效、X 轴左端刻度显示成最新时间、卡片小字里的"覆盖多久"算成 0 秒。脚本先让设备发一条新报文制造这个场景再刷新页面，断言刷新后 `ts` 仍严格非递增、首条仍是库里最早那条、跨度仍是 10 小时；然后**手动把首条挪到末尾**造出坏顺序，验证归并修复真的会被触发（这里有个坑：破坏点在数组**尾部**，断言要查 `ts[len-1] < ts[len-2]`，查头部是查不出来的）。
* **阶段 H —— 离线判定阈值要跟着设备上报节拍走。** 写死 15 秒的话，现场 60~80 秒上报一次的 PLC 每来一条数据、过后 15 秒卡片就变灰显示「无数据」，剩下 80% 的时间都挂着这个标签，很容易被误认为"平台没在收数据"。现在取最近 12 个间隔的中位数 ×3 并夹在 [15 秒, 5 分钟] 之间。脚本用假的 `ts` 数组分别断言 2 秒/点、80 秒/点、200 秒（撞上限）、真断了 10 分钟四种情况。

`verify-hover.js` 走的是**真实输入链路**：用 CDP 的 `Input.dispatchMouseEvent` 派发真正的鼠标移动（不是直接调内部函数），然后断言提示框里的**数字就是该曲线 `data[i]` 本身**（不是插值、不是重新算的）、多曲线时三条线取到的时间戳**只有一个**（证明确实是同一时刻，不是各指一个点）、十字线画在**覆盖层**上而主画布一个 `arc` 都没多画。它同时勾住 `arc / moveTo / lineTo / fillText` 并把 `canvas.className` 一起记下来，这样"画在哪一层"是可断言的 —— 覆层上出现文字就说明刻度被重复画了。

它还顺带验了刻度密度：断言大图的 Y 刻度不少于小图且 `>= 5` 档、放大的 X 时间标签 `>= 4` 个、并且**任意长度下抽稀后仍然等距**（`thinTicks` 穷举 2~40 档 × 上限 2~12 逐一检查，这条一开始就是错的 —— 用 `Math.round(i*(m-1)/(n-1))` 选下标会得到 `[0,15,35,50]` 这种不等距子序列）。

`verify-group.js` 盯的是分组卡片最容易错的几件事：

* **前缀必须按 `/` 切。** `plc` 只收 `plc/…`，不能把 `plc2/…` 抢走 —— 脚本两头都验：正向（`plc/…` 路由进 `plc` 卡）、反向（先建一张 `plc/*` 的组卡，断言它只收 `plc2/…`）。主题框填 `plc/*` 也要归一成裸前缀，不然卡片建出来了、副标题也对，却一条曲线都匹配不上。
* **一条主题一条曲线，且不能串数据。** 两条曲线的 key 里带着各自的主题（`__topic__:plc/DB1.DBW290|…`），脚本让电量报 `100~330`、电流报 `5000~5077`（量纲差 50 倍），一断言就知道有没有把两路画进同一条线。
* **刷新页面后每个成员主题分别回填。** 只补最新那个主题是最容易写出来的错，所以它让 7 个主题各发几条、刷新后断言画出来的还是 6 条、`+N` 还是 1 个。
* **勾选只画勾上的、不勾的留着显示值、删除才算撤下卡片。** 勾一个主题 → 断言只剩一条曲线、`picked` 落到卡片上、副标题变 `1/2 个点位　曲线 1 条`、**没勾的那个照样在图例里显示实时值（空心点、不画线）**、且它不抢卡片大字；再断言**勾选框的值（主题名）没被当成字段路径混进 `card.fields`** —— 单主题卡的"字段勾选"和分组卡的"主题勾选"共用同一个容器，收集时必须按 class 分开。7 个成员时挨个勾，第 7 个必须被上限弹回去；最后点「取消」断言乱勾的东西没有被存进卡片。
* **取消上板 / 加回**（阶段 B3）：弹窗里 ✕ 或侧栏点 ✓ 都是撤下 → `card.removed` 记一笔、曲线与实时值一起从卡片消失、**从路由上就断了**（删过之后它再上报也不会被拉回来，脚本专门发一条 8888 验证不是只靠"不勾"）→ 侧栏那一行变成空心点 + 虚线 `+` → 点 `+` 直接加回原分组卡（断言**没有多出一张单主题卡**）→ 点 ✓ 再撤下 → 弹窗底部「已从卡片删除（N）」点「恢复」，**曲线带着历史一起回来**（这条同时守住"放回来要重新补历史"的回填去重粒度）。
* **纯回填出来的曲线也得有当前值。** 把某条曲线切到别的字段（`|value`）再切回「自动」，脚本断言两次都有 `num !== null 且 text !== '—'` —— 新曲线一开始只有回填数据、没有实时报文打到它头上，早期版本就是这里让卡片大字和图例挂着「—」，看着像"切了字段数据就没了"。
* **同前缀自动合并**（阶段 G）：关着开关时两张单卡保持原样 → 打开后 `merged=2` 只剩一张 `dev` 卡 → 两个主题各一条曲线且不串数据 → 曲线不是空的（合并后立刻从库回填）→ 同前缀的新主题直接进这张卡不再冒新卡 → 侧栏那个复选框真的把开关落到 localStorage → 关掉后 `reconcileAutoGroups()` 是彻底的空操作。
* **超时无数据提示**（阶段 H2）：用假 `ts` 把某个点位"按回 10 分钟前"，分四个场景断言 —— ⓪**一个间隔都估不出来时不许判掉线**（阈值必须是 `null` 而不是 15 秒兜底，这是线上实测踩出来的误报）①只有 A 掉线：`staleTopics()` 只认它、标签 `无数据 1/3` 并带 `is-part`、图例那行撤成「—」且悬停写清停了多久、**卡片大字与 Y 轴刻度都改挑在线点位**（不再拿掉线点位的旧值/量程）②三个点位全停：标签 `无数据 3/3`、`is-part` 撤掉、整卡 `is-stale`、大字老实显示「—」③数据回来：标签回「正常」、`is-stale`/`is-part` 无残留、顶栏汇总自动收起。顶栏那条汇总与"边沿弹一次"的 toast 也在同一阶段验。
  > ⚠️ 造数据时**每个点位要灌 3 条、间隔正常**：`reportIntervalMs` 取"点数最多那条曲线"的间隔中位数，一个点位只灌一条会造出十几分钟的假间隔，阈值被抬到 5 分钟上限，"掉了 10 分钟"反而不算掉线（探针自坑，踩过）。

它最后两条属于"看一眼就知道写错了"的自检：**图例高度必须是整行倍数**（六条曲线时图例占两行，`10.5px × 1.35 = 14.175px` 配 30px 上限会露出第三行 1.65px，屏幕上就是"半截字"），以及**图例和卡片脚部都不能被卡片裁掉**。

这些脚本（除 `check-ids.js` 外）都在临时目录里跑，**不会动正式实例的 `config.json` 和 `data/history.db`**，跑完自动清理。改完前端后跑一遍，比手点界面可靠。

### 给老库补「数值」列

`num` 那列是给导出 CSV / 统计用的。老版本只把「裸数字」报文认成数值，设备这种 `{"dataType":"Int16","value":"0",…}` 落下来 `num` 全是 `NULL`，导出的 CSV「数值」列整列空白（曲线本身不受影响 —— 前端自己从 `json` 里挖字段，但导出和统计吃的是这一列）。新版本会在收报文时就抽好，已经存下来的老数据用这个脚本补：

```bash
node tools/backfill-num.js              # 只统计能补多少行（不写库）
node tools/backfill-num.js --apply      # 真的写库，写之前自动备份一份 history.db
```

**默认只统计不写库** —— 这是用户的历史数据，不能因为版本升级就悄悄改动。抽数值的规则（字段优先级、大小写、时间戳排除、多值放弃）见 `verify-num-extract.js`。

## 五、历史数据（落盘，重启不丢）

曲线能回溯多久，由**保留天数**决定，而不是「从打开页面那一刻才开始记」。

- 每条 MQTT 消息都会被追加写进 SQLite：`data/history.db`（用 Node 22 自带的 `node:sqlite`，**不用额外装任何东西**）
- **平台重启、电脑重启、页面刷新都不丢**；刷新页面后曲线会按卡片的 **X 轴时间范围**（选「全部」就是保留期内的全部）从库里回填，接着往后画
- 默认保留 **7 天**，在左侧「历史数据」面板里改（面板给出 1 / 3 / 7 / 15 / 30 / 90 / 365 天的快捷值，也可以自己填 1~3650）
- 另有一道兜底：总行数上限 200 万行，超了就从最旧的开始删，防止把盘写满
- 「导出 CSV」把保留期内的数据导成表格（带 UTF-8 BOM，Excel 双击打开不乱码；也带主题、数值、原始载荷三列）
- 「清空历史」把内存缓冲和落盘库一起清掉，**看板卡片保留**（曲线从头开始，删了无法恢复，会弹确认框）

面板上实时显示：已存多少条、占用多少空间、最早一条是什么时候、当前保留几天。

> **写入是攒批的**（约 400ms 一次事务，或攒够 500 条），所以高频上报也不会把磁盘 IO 打满。读接口前会先把队列刷干净，所以「设备刚发的数据立刻就能查到」。
> **Node 版本低于 22.5** 时没有 `node:sqlite`，平台会自动降级成**只存内存**，面板上标注「未落盘」并说明原因，其它功能完全不受影响。

**占用估算**：一条 JSON 报文约 200 字节（含索引）。按每台设备 1 秒 1 条算，一天约 8.6 万条 / 20 MB 上下，7 天约 140 MB。若设备是**变化才上报**（像 PLCTesting 那样一条几十秒），占用会小一两个数量级。

**库文件位置**：`MqttMonitor/data/history.db`（另有 `-wal`、`-shm` 两个伴随文件，属正常现象；`data/` 已加入 `.gitignore`）。想换目录：改 `config.json` 里的 `history.dir`，或用环境变量 `MQTT_MONITOR_DATA_DIR`。

**保留天数改了什么时候生效**：改的一刻就会按新天数清理一次（面板上会提示清掉多少条），配置文件同步落盘，重启后仍然记得。

## 六、配置文件

配置存在 `config.json`（首次运行自动生成，删掉即恢复出厂设置）。主要字段：

```jsonc
{

    }
```

## 七、常见问题

**连上了，但一个数据都没有**
先看顶栏有没有红色提示「未订阅任何主题」。取消订阅时如果把最后一个（比如 `#`）点掉了，平台就收不到任何数据，界面只表现为卡片全是"无数据"。到左侧「连接设置」里重新订阅，或直接点「订阅全部（#）」。取消最后一个订阅时平台也会弹确认框拦一下。

**卡片右上角一直灰着写「无数据」，可曲线上明明有点**
离线阈值是**按每条曲线实测的上报节拍**算的（最近 12 个间隔的中位数 ×3，夹在 [15 秒, 5 分钟] 之间），不是写死的秒数。把鼠标停在那个标签上会显示判据，例如「上报节拍约 60 秒」，那阈值就是 180 秒 —— 超过 180 秒没有新数据才会变「无数据」。闸门里常见的 60~80 秒上报周期不会被误判。
**估不出节拍时不会判掉线**（阈值是 `null`）：页面刚打开、历史还没回填完的那几十秒里，卡片手上可能只有一两条报文，这时"不知道它多久发一次"，不该当成"它掉了"。等回填完成或再收一两条就会自动开始判。
标签现在会直接写清停了多久（`无数据 3 分`），分组卡则写 `无数据 1/3`（几个点位掉了）。真要排查掉线就看悬浮提示里的"停最久的是 X：N 分"：N 明显大于节拍 ×3 才是真停了。顶栏那条汇总会给出一行全景，点一下就跳到出问题的卡片。

**分组卡里有一个点位不发了，怎么没有提示？**
现在有了。这是"卡片级判定"的盲点：以前只看"卡片上最新的一条"，别的点位还在发，整张卡就显示「正常」。现在逐个成员判定 —— 标签变 `无数据 1/3`、图例那一行撤成「—」并标橙、顶栏汇总里也会列出来。刷新页面后仍按各点位自己的节拍重算。

**端口 1883 被占用（本机已有 mosquitto 等）**
平台会自动改用 18830，并在启动日志和界面上提示。也可以在面板里手动改成别的端口（比如 1884）。

**端口 8090 被占用**
`node server.js --port 8091`

**设备连不上内置 Broker**
1. 确认设备填的是平台电脑的局域网 IP，不是 `127.0.0.1`
2. Windows 防火墙可能拦了入站——放行 1883 端口：
   `netsh advfirewall firewall add rule name="MQTT" dir=in action=allow protocol=TCP localport=1883`
3. 确认设备和平台电脑在同一网段、能互相 ping 通

**想看设备连上来的详细情况**
左侧「内置 Broker」面板的「已接入设备」列表里有 ClientId、IP、订阅主题、发布条数/字节、在线时长。

**数据量很大怎么办**
平台把消息按 100ms 合并成一批再推给浏览器，普通工况没问题。如果每秒上万条，建议把订阅收窄成具体主题（别用 `#`），并把看板卡片数量控制住。落盘那边是攒批写入的，不会每条都落一次盘；实在太大可以把保留天数调小，或把 `history.enabled` 关掉退回纯内存。

**平台重启后，曲线是不是要重新等数据？**
不用。库里已经存着的会按卡片的 **X 轴时间范围**回填（「全部」就是保留期内全部），再从最新一条接着画。真正决定"能回看多久"的是左侧「历史数据」面板里的保留天数。

**曲线上的刻度值太小看不清**
卡片只有 44px 高，刻度是挤进去的。**单击卡片**放大到 160px，Y 轴刻度会从 2 条增到 3~5 条，X 轴也会补出中点时间。再单击还原。

**选了「最近 1 小时」，怎么曲线只显示了 10 分钟？**
先看卡片右下角的小字，它会写清这次的实际情况（`1320/5001 点（抽稀） · 10.0 小时 · 库内 30000 条`）。然后按这两种情况对号入座：

| 小字里写的 | 说明 | 怎么办 |
|---|---|---|
| 跨度 ≈ 你选的窗口 | 正常，数据是够的 | — |
| 跨度短于窗口 + 「库内 N 条」也不多 | 设备本来就只发了这么多 | 等设备攒够；或查设备是否掉线（卡片会灰显「无数据」） |
| 跨度短于窗口 + 库里有更多 | 窗口太长、库里那份还没被拉回来 | 刷新页面；或把窗口改一下再切回来（会自动从库里补） |

顺带：平台重启 / 刷新页面后，曲线会先按窗口从库里回填，所以窗口设置不会让你"白等一段"。

**曲线太平、看不出细节**
曲线是**按索引等距**画的，点多了自然平。想看清一小段就选「最近 5 分钟」这类短窗口 —— 平台会从库里把那一小段时间的数据取回来画满，而不是把长曲线对半截。

**「全部」到底是多少？**
= 落盘库里该主题在**保留期内**的全部数据，超过 5000 个点时在服务端**均匀抽样**（首尾一定保留），保证整段都在画面上。想看某一个原始点的精确值就导出 CSV。

**历史库占地方了，能直接删吗？**
停掉平台后直接删 `data/` 整个目录即可（下次启动会重建空库）。不想删文件就点「清空历史」，或把保留天数改小 —— 改完立刻按新天数清理一次。**别在平台运行时手动删 `history.db`**，会写不进去。

**安全提醒**
内置 Broker 默认允许匿名接入，方便现场调试。放到公司网络上建议在面板里设置账号密码；平台自身的 Web 界面没有鉴权，别直接暴露到公网。

## 九、二次开发提示

浏览器控制台里有全局对象 `MQTTMonitor`：

```js
MQTTMonitor.state.cards                          // 当前卡片数据
MQTTMonitor.state.cards[0]._chart                // 这张卡「上次到底画了什么」：
                                                 //   {winMin, points, rawPoints, dropped, spanMs, series, fromTs, toTs}
                                                 //   points=真画到画布的点、rawPoints=抽稀前、dropped=抽掉多少、spanMs=铺开多久
                                                 //   排查"窗口生效没、画了几个点、为什么看着不全"全看它
MQTTMonitor.state.ui.chartWindowMin              // 看板全局 X 轴范围（分钟，0 = 全部）
MQTTMonitor.state.topics                         // 主题清单
MQTTMonitor.state.history                        // 历史库统计（条数/占用/时间范围/保留天数）
MQTTMonitor.createCard({ topic: 'x/y', unit: '℃', high: 80, windowMin: 30 })  // 代码加卡片
MQTTMonitor.markDirty(card)                      // 强制重绘某张卡（改完卡片属性后调）
MQTTMonitor.normalizeSeriesTs(card)              // 把曲线的 ts/data 归正序（怀疑"刻度乱"时先调它，返回是否改过）
MQTTMonitor.ensureCoverage(card)                 // 按当前窗口从历史库补数据（返回补了多少点）
MQTTMonitor.reportIntervalMs(card)               // 这条曲线实测的上报节拍（ms，估不出来是 null）
MQTTMonitor.staleThreshold(card)                 // 这张卡的离线阈值（= 节拍×3，夹在 [15s, 5min]）；**估不出节拍返回 null（判不了）**
MQTTMonitor.isStale(card)                        // 现在算不算离线（**卡片级**：整卡一条新的都没来）
MQTTMonitor.staleSummary()                       // 看板全景：{cards:整卡静默的卡, partial:[{card,topics}]}
MQTTMonitor.staleTopics(card)                    // 分组卡里哪些成员主题自己停发了
MQTTMonitor.topicSilenceMs(card, topic)          // 某个成员主题停发多久了（ms）
MQTTMonitor.hoverMove(card, {clientX, clientY})  // 用代码模拟悬停取点（排查"提示框读到了什么"）
MQTTMonitor.hoverClear(card)                     // 收掉十字线与提示框
MQTTMonitor.state.cards[0]._hoverHit             // 上次悬停到底取到了哪几个点：{ts, x, rows:[{key,i,v,ts}]}
                                                 // v 是直接引用 data[i]，不是插值出来的
MQTTMonitor.api('/api/broker')                   // 直接调后端接口
MQTTMonitor.api('/api/ui', { ui: { chartWindowMin: 30 } })      // 改全局 X 轴范围
MQTTMonitor.api('/api/publish', { topic: 'a/b', payload: '1' })  // 平台下发
MQTTMonitor.api('/api/history?topic=plc/x&limit=500')  // 取某主题的历史（优先读库）
```

后端也对外开放了历史落盘接口，方便做对接：

| 接口 | 说明 |
|---|---|
| `GET /api/history?topic=&limit=&since=&windowMin=&sample=1` | 某主题历史（**优先读库**，库不可用才退回内存）。`windowMin>0` 时按库里最新一条往前算窗口起点；`sample=1` 让 `limit` 从"最多返回多少条"变成"分辨率上限"——整段**均匀抽样**到约 limit 个点、首尾必留（不抽的话 1 小时里有 3.6 万条，只取最新 5000 条等于只画了最后 8 分钟） |
| `GET /api/history/span?topic=&windowMin=` | 这个主题到底有多少数据：`{db:{count,firstTs,lastTs}, mem:{count,firstTs,lastTs,inWindow}, dbSince, dbInWindow}`。卡片旁"库里共 N 条"和"选了窗口却只显示一小段"的说明都靠它 |
| `GET /api/history/stats` | 条数、占用、最早/最新时间、保留天数、库路径 |
| `GET /api/history/topics?limit=` | 库里各主题的条数与最后时间 |
| `POST /api/history/keep-days` `{keepDays}` | 改保留天数并立即清理一次 |
| `GET /api/history/export?topic=&days=&max=` | 导出 CSV（带 BOM，直接下载）。「数值」列来自落盘库的 `num`，见上面「给老库补『数值』列」 |
| `POST /api/history/clear` `{topic?}` | 清空历史库（不传 topic = 全清，同时清内存） |

REST 接口一览：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 配置 + 连接状态 + 主题 + Broker 台账 |
| POST | `/api/connect` | 连接 broker（`{connection, subscriptions}`） |
| POST | `/api/disconnect` | 断开 |
| POST | `/api/subscribe` `/api/unsubscribe` | 增删订阅 |
| POST | `/api/publish` | 下发消息 |
| GET | `/api/topics` `/api/history?topic=&limit=` | 主题清单 / 历史数据 |
| GET/POST | `/api/broker` `/api/broker/start` `/api/broker/stop` | 内置 Broker 状态与启停 |
| POST | `/api/broker/sim` | 数据模拟器开关 |
| POST | `/api/broker/disconnect` | 断开指定客户端 |
| POST | `/api/broker/connect-self` | 让平台接入本地 broker |

WebSocket：`/ws`，帧格式 `{type, ...}`，类型有 `status` / `stats` / `messages` / `topics` / `broker` / `reset`。
